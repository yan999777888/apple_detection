# 数据条件审计与手机先行采集协议

整理日期：2026-11-12。按用户最新要求，执行顺序是 **本地已有数据→公开现成数据→必要时补标现有图像→最后才自采**。用户愿意用手机或相机采集离线多视图，机械臂实验后补，但第3–7节采集协议现为备选，**不是当前任务，不要求立即采集**。本文件区分已核实事实与待实施方案；没有新增实测样本，也没有将未知属性补成真值。

## 2. 已完成实验给下一步的约束

真值 ROI 属性分类的三种子对照中，普通 CE 优于逆频率加权：stage macro-F1均值0.91407对0.74096，SSDA为0.93678对0.92791。这些是已知真值裁框后的分类，不能代替全图系统性能。

固定640/960开发集回放中，stage的FP+FN由7增至15，SSDA由150增至202；10%预算低置信度复核仍存在增加漏检或收益被误检抵消的情况。当前证据不支持直接宣称“低置信度就补一次高分辨率”有效。GT oracle只证明两套输出之间存在选择上限，不能作为部署策略结果。

HDF全图浅层特征分类开发准确率97.47%，仅8像素外围也达到95.78%。这说明外围信息与类别高度关联；外围可能含苹果，不能将其直接写成纯背景的因果证明，也不能据此宣称整果分级已可靠。

PApple 新 stage YOLO26n run `runs/papple_yolo26n_seg_640_e40_s20261106` 的最后完整记录为epoch9/40：box AP50/50:95为0.70635/0.53925，mask为0.70595/0.51699。P/R是开发集最大平均F1点，不是固定置信度0.25。该任务不能与旧全局 Base+Small amodal框94.43%混比。

## 3. 首轮采集目标

只有现有/公开数据无法补足同果多视图与参考真值、并决定启用自采时，才先做 **30–50颗不同物理苹果的流程试采**，目的是检查身份登记、视图关联、参考标注、错误类型和耗时记录是否可用。这不是充分的论文样本量，也不将视频帧数当作独立果实数。正式样本量和类别配额在试采后按错误事件数量、目标区间宽度、组间差异和可采条件另行冻结。

优先使用实际枝头果；暂时只有采后果时，可以固定在支架上做离线机制试验，明确标记为 `bench_fixed`，不能把结果称为枝头采摘验证。尽量包含成熟外观不同、可见表皮缺陷、表面看似完好、遮挡、反光和背光情况。试采可主动补足稀有情况，但应登记招募方式；后续需要另设自然分布样本，不能将均衡挑选数据当作真实果园发生率。

初版只研究外观阶段与可见缺陷证据。没有糖度、硬度、淀粉等实测时，不建立生理成熟度真值。没有明确执行的等级标准时，先用 `visible_defect_present`、`no_defect_found_in_review`、`unassessable` 三种复核状态，不硬造商品一级/二级。

## 4. 现场照着做

1. **先编号，再拍。** 每颗苹果分配永久 `fruit_id`，例如编号规则可由项目+日期+流水号组成，但编号本身不作类别依据。登记果园/场所、树或采后批次、品种（未知填null）、采集日期、场景组和相机。先拍带编号的登记照；正式预测画面不要出现与等级相关的标签。即使换天或换相机，该果仍沿用同一ID。
2. **固定果实，移动相机拍探索视图。** 枝头苹果不为拍照而转动、采摘或扒开叶片。台架苹果也固定姿态。先拍自然正面起始视图，再从实际可到达的左/右/上方移动相机；建议每条轨迹从4–6个观察位置起步，每个位置短暂停留，保存原视频与所选清晰帧。没有空间时就记录不可到达，不能为了凑角度生成不存在的动作。
3. **完整保存轨迹和耗时。** 连续视频用于保留转移顺序；记录相机帧时间、离开上一观察位置时间、到达并稳定的时间以及采用的帧。若只有手工估计时间，填写测量方法及不确定性，不能称精确机器人动作耗时。帧率不稳定时用媒体时间戳，不简单使用“帧号÷标称FPS”。
4. **区分新视角与重复帧。** 同一位置连拍/相邻帧归同一个 `view_group_id`；横移很小但画面相似的帧不能作为多个独立观察。可用纹理、枝干和可见缺陷位置人工核验视角变化。没有姿态与表面重建时，只记录可见证据变化，不声称覆盖了多少百分比的果面。V/A二维面积比不能替代三维果面覆盖率。
5. **不要把变焦当作补看背面。** 原分辨率文件保留，不开美颜、滤镜或AI补画。尽可能保持同一视频内焦距、曝光和白平衡策略稳定，并登记是否自动变化。光学距离变化、数字裁剪/放大和真实视角变化分别标记。模糊、反光、严重遮挡帧保留并注明，不只留下好看的帧。
6. **结束探索后再采参考。** 若允许采摘，取下同一苹果，在均匀光照下转动果实，复核侧面、顶部和底部；保存高分辨率照片及编号。这一组是 `reference_only`，绝不作为前面策略可调用的视图。若不能采摘或不能看全表面，则参考完整性标记为部分，整果结论保持unknown，不把有限视图的“未见缺陷”写成整果无缺陷。
7. **标注实际可见证据。** 每张探索图标苹果可见区域/实例ID、当前可见的缺陷区域和外观阶段（不清楚则unknown），并记录遮挡、截断、反光、模糊。采后新损伤与采前已有缺陷分开记录；拿不准出现时间则该项不能作为采前等级的确定真值。
8. **两人复核关键结论。** 参考复核尽量由两名标注者独立完成，优先看实物/参考照片，不先看模型输出；分歧经复核仍不一致则保留 `unassessable`。等级规则、缺陷面积量法、严重程度阈值和仲裁过程在正式实验前写成版本化规则，不能看完模型成绩后反向调等级。

手机当前可以先做RGB离线试采。没有RGB-D和相机标定时，暂不报告三维定位误差；不要求先完成机械臂手眼标定才能拍这个视觉试采集。

## 5. 数据划分与未来帧防泄漏

- 同一 `fruit_id` 的全部轨迹、重复帧、参考照片和后续相机数据必须位于同一分区。
- 以树/采集批次、连续场景序列、采集日期和地点建立分组；存在共享果实或同一连续场景的记录应合并为同一连接组，再分配train/calibration/test。不能仅随机拆视频帧。跨日期的同果也不许跨split。
- 试采全部标记为 `pilot_development`，主要用于调流程。正式冻结测试集应来自未用于设计阈值/规则的独立采集组；已反复查看的公开dev不重新命名为test。
- 校准集用于设置信心阈值、停止条件和拒判规则；独立test只用于冻结方法后的评估。缺少足够独立组时如实报告，不强行分出很小的“独立集”。
- 每一步策略只接收当前已访问视图及当时可用的相机/动作信息。未访问视图的模型分数、标签、可见缺陷、参考等级和未来图像特征，不能进入动作排序输入。
- 离线回放时，先记录策略选择的动作，再揭示该动作对应的后续帧。GT和全序列只供独立评估器事后评分。oracle选择最佳未来帧只作上限对照，不能作部署方法。
- 一条轨迹只支持实际记录的转移；不能允许任意两个帧间免费跳转。手机路径的 `capture_reachable` 不等于机械臂可达；`robot_reachable` 未验证时为null。不可达或未测耗时的转移不参与机器人时间收益主张。
- 若为了回放采集多个可选分支，应从相同起始姿态分别重放并明确记录边，保持果实、枝叶和光照尽可能稳定；状态明显变化的分支标为不同场景，不强行视为同一反事实选择。

## 6. 最小实验对照与记录指标

同一感知模型、同一起始图像与同一可调用视图集合，比较：单视图、固定2/3视图、随机同动作预算、低置信度补看、预测净收益补看。随机种子事先冻结。还应有仅预测风险而不预测可补救性的消融，避免把全部收益归给新机制。

先在探索训练组拟合/校准策略，test阶段GT不进入策略。报告逐果外观判断、关键缺陷漏检、错误高等级判定、拒判比例、正确且被接受的果实占全部目标的比例、补看次数及计算/转移时间。困难目标拒判后仍在全部GT分母中。按独立果实和采集组做不确定性分析，不按视频帧伪造样本量。

阶段性时间指标必须分开：手机轨迹转移耗时、GPU图像处理服务时间、离线总回放成本。它们不能直接换算为D405机械臂闭环FPS或每小时采摘量。固定观察预算与固定实际时间预算也分别比较，不以动作数相同替代耗时相同。

## 7. D405与机器人后续迁移

先用D405对一部分新果实采同样的观察/参考协议，形成与手机域分开的数据；相同物理果实若同时由手机和D405采集，必须绑定同一split。模型微调/校准只能使用训练和校准组，留出未见果实及场景检查迁移。

机器人验证另记录同步RGB-D时间戳、内参、曝光、深度有效比例、动作起止、关节状态、实际可达性与碰撞限制。可用停靠关键帧进行第一次端到端验证，再测试运动接近。机器人动作需要已有安全控制流程，不由本数据模板直接触发。

在目标被锁定后的局部任务上验收20Hz，应测相机取帧至有效分割/定位输出的延迟、P95、丢帧和定位有效率；离线YOLO单模型速度仅是其中一项。完整论文系统指标还需真实等级目标箱、投放正确性和采摘周期，不由公开缺陷检测AP推出。

ASABE文章 DOI `10.13031/ja.16670` 的官方摘要声明提供多视图数据与软件，但本次尚未核验到可下载数据实体、使用许可和身份/划分文件；不能写作“本地已有可用数据”。其公开情况可继续核查，不能因此跳过当前实际采集准备。

正式论文数据规模、外观等级定义和机器人实测安排在试采质量审查后再冻结。此协议是可执行的第一步，不是期刊录用保证。
