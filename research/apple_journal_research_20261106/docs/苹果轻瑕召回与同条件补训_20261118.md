# 苹果轻瑕召回与同拍摄条件补训

## 为什么补这些照片

AFruitDB 固定划分为 315 张训练、57 张验证、110 张历史留出。在这 315 张训练图中，98 张好果与 11 张轻瑕果来自同一连拍组，另有 109 张轻瑕果来自同一果托拍摄组。每次抽样先选等级和拍摄组，再选照片，避免长连拍主导训练。历史留出此前已查看，单列为回归检查。

Woo 的左、右、俯视机位各自同时有完整果面和轻伤果面。核对作者瑕疵多边形和图像后，保留 48 张可见面无明显伤、10 张有可辨认的小划伤。35 个时间戳可能反复拍到同一果，整场仅入训练。原作者提供划伤标注；人工分级专家未复核这些品质代理类别。项目用原图及多边形做了视觉核对。公开的 Harvard 好果与不完美果照片在背景、取景上差异明显，未用于配对训练。[同条件训练果面与果园挑战数据卡](同条件训练果面与果园挑战数据卡_20261118.md) · [Woo 作者数据](https://universe.roboflow.com/woo-wwyog/orchard-apple-defect-segmentatio/dataset/1)

FruitLife 提供同一实物随储藏变化的原图、果实掩膜与作者逐帧等级。六颗苹果覆盖三种储藏条件，先按实物编号在每种条件分出一颗供训练、一颗永久留出。训练侧 15 张阶段 0 与 15 张阶段 1 提供同果外观变化的配对参考。阶段 1 指仍圆滑但失去光泽或开始褐变；不能把它等同于划伤。评估分开报告阶段 0 至 4，阶段 2 保留原定义，阶段 3、4 单列严重萎缩和塌陷。果实以外的色卡、标尺和背景在这项对照中用作者掩膜排除。[FruitLife 作者数据与许可](https://doi.org/10.5281/zenodo.23589223)

## 训练与选型约定

原三级分级、原成熟度和原划伤/虫伤权重均单独保留。主要对照从先前真实裁片训练的 MobileNetV3-Small 权重开始。对照和补训共用 AFruitDB 每次抽样、图像增强、优化器及 360 步预算，补训臂同时学习同机位好/轻图片之间的相对差异。输出采用固定三类最大得分。自动场景只有恰好一个果实时才用整图等级复核，零果或多果保留在分母。

开发集选型同时检查轻瑕召回、重瑕判好、重瑕判对、好果判对与整体正确数。先按同一规则选定一份权重，再做 110 张历史回归、独立果面检查和整套测速。增加轻瑕预测可能让好果降级，需一起观察。[预定复核条件](../experiments/grade_matched_review_v1/field_protocol.json)

## 训练阶段实测

下表均为相同的 57 张 AFruitDB 验证图。共 25 张好、15 张轻瑕、17 张重瑕，6 张场景无法唯一关联。每个常规训练臂各执行 20 轮、360 步。224 与 320 的比较回到原始图片重新生成各自尺寸的裁片。模型选择只使用验证集。验证集轻瑕找回的 3 张均在同一个拍摄组，新增降级的 1 张好果也在该组。

| 自动场景分级 | 好果判对 | 轻瑕判对 | 重瑕判对 | 重瑕判好 | 总分对 |
|---|---:|---:|---:|---:|---:|
| 原发布模型 | 21/25 | 1/15 | 9/17 | 8/17 | 31/57 |
| 按组均衡重放 AFruitDB | 21/25 | 0/15 | 17/17 | 0/17 | 38/57 |
| 加 Woo，224 像素 | 20/25 | **3/15** | 17/17 | 0/17 | **40/57** |
| 加 Woo，320 像素 | 21/25 | 1/15 | 17/17 | 0/17 | 39/57 |
| 加 FruitLife，224 像素 | 20/25 | 1/15 | 17/17 | 0/17 | 38/57 |
| 加 Woo 和 FruitLife，224 像素 | 20/25 | 2/15 | 17/17 | 0/17 | 39/57 |

另在固定的原裁片对齐模型上试过只允许“好→轻”的小分支，用同一骨干的中层局部特征学习裂痕证据。仅 AF 与加 Woo 两种训练的自动轻瑕正确数都是 0/15，未入选。最终在外部复核前冻结 Woo 224 的第 2 轮权重，其他候选均未查看外部果实的预测。[逐臂验证记录](../experiments/afruit_grade_matched_v1/source_selection.json) · [最终选定权重的哈希与候选排序](../experiments/grade_matched_review_v1/frozen_candidate.json)

## 110 张历史回归

自动链路在长边 1280 的 110 张图上完整重推。两版检出的果实数量、果实裁框及成熟度类别逐图一致，划伤与虫伤框、归属和得分在 110/110 张上相同。29 张因为零检出或多实例而未唯一关联，保留在总分母内。以下四列依次是预测好、轻、重、未唯一关联。

| 作者标签 | 原版自动 | 本轮自动 | 原版已知单果整图 | 本轮已知单果整图 |
|---|---:|---:|---:|---:|
| 好（56） | 44 / 1 / 0 / 11 | 39 / 6 / 0 / 11 | 56 / 0 / 0 / 0 | 47 / 9 / 0 / 0 |
| 轻（37） | 25 / 2 / 0 / 10 | 13 / 14 / 0 / 10 | 35 / 1 / 1 / 0 | 14 / 22 / 1 / 0 |
| 重（17） | 6 / 2 / 1 / 8 | 0 / 6 / 3 / 8 | 0 / 1 / 16 / 0 | 0 / 4 / 13 / 0 |
| 三级分对 / 全体 | 47/110 | **56/110** | 73/110 | **82/110** |

自动裁片轻瑕召回从 **5.41% 提至 37.84%**（增加 32.43 个百分点），多找回 12 张原判好的轻瑕。原先 6 张判好的重瑕中，3 张纠正为重、3 张改判轻；另有 1 张原判重的图变为轻。17 张重瑕中只有 9 张能在图中唯一对应，8 张仍待确定。对已知单果整图，轻瑕召回从 2.70% 升至 59.46%，好果正确数少 9 张。不能用整图结果代替自动找果的结果。

预先规定自动场景好果判对至少 40/56，本轮为 39/56，少 1 张。虽然预测“好”的精确率从 44/75（58.67%）升至 39/52（75.00%），更多真实好果被送入轻瑕级。因此保留原默认权重，本轮权重作为可以单独运行的候选。[定量回归与按批结果](../experiments/grade_matched_review_v1/field/regression.json) · [逐果改判实图](../experiments/grade_matched_review_v1/field/逐果改判对照.html)

## 跨来源检查

同一份冻结权重和原版分别按已提供的果实图像在 CPU FP32 下推理。这项检查检验分级器的迁移能力；果园自动检测由上节验证。FruitLife 按实物分出三颗新果，表中的多帧有时间相关性。HDF 的旧固定面板只有新鲜/腐烂来源类别。Penn State 的独立日期小组包含 4 张带小面积损伤的果面及 4 张有明显腐烂的果面，分级来自作者病变多边形与可见外观复核。

| 来源、作者标签和计算项 | 原版 | 本轮 |
|---|---:|---:|
| FruitLife 阶段 0，判好 | 29/29 | 14/29 |
| FruitLife 阶段 1，判轻 | 0/21 | 13/21 |
| FruitLife 阶段 3，判好 | 37/71 | 15/71 |
| FruitLife 阶段 4，判好 | 9/44 | 2/44 |
| HDF 有腐烂标记，判好 | 69/200 | 4/200 |
| HDF 新鲜，判好 | 52/69 | 28/69 |
| HDF 新鲜，判重 | 2/69 | 36/69 |
| Penn State 小面积果面损伤，判轻 | 1/4 | 2/4 |
| Penn State 明显腐烂，判好 | 0/4 | 1/4 |

换来源后好果降级的风险更大。FruitLife 找回的 13 张早期变化图中，11 张来自同一颗苹果，而这颗果的 11 张新鲜期图也全部被判轻。HDF 的结果表明，减少有腐烂标记的苹果被判好的同时，会把一部分新鲜果严重降级；Penn State 的小样本又出现 1 次新增腐烂放行。这些结果支持把候选用于辅助提示，尚不足以替代人工验级或自动放行。[各阶段、每颗实物及两版全部计数](../experiments/grade_matched_review_v1/external/results.json) · [FruitLife 数据的标注定义与实物分组](FruitLife同实物储藏外观辅助数据_20261118.md)

## 全流程实测速率

RTX 4060 Laptop，成熟度实例分割、原划伤/虫伤模型、三级分级、掩膜/框回传 CPU 及绘图全部运行。每种模式 5 帧预热，同一组 20 张实际照片循环 30 次，串行处理 600 帧，图片预先解码。计算过程含当前图像预处理，相机取流、磁盘解码、显示器刷新及机器人动作未纳入。相机已经交付 1280 长边画面与电脑先收到 4K 再缩图的两种成本分别实测。

| 输入和模式 | 运行分级的帧数 | 含绘图平均时延 | P95 时延 | 含绘图 FPS |
|---|---:|---:|---:|---:|
| 已是长边 1280，自动找果 | 540/600，合计 660 份裁片 | 44.95 ms | 50.61 ms | **22.25** |
| 已是长边 1280，已知单果且每帧分级 | 600/600 | 47.32 ms | 54.17 ms | **21.13** |
| 已解码约 4K，电脑先缩到 1280，再自动找果 | 540/600 | 约 69.5 ms | 75.11 ms | 14.39 |
| 已解码约 4K，电脑先缩到 1280，再对已知单果分级 | 600/600 | 约 72.2 ms | 78.95 ms | 13.86 |

约 20 FPS 在相机尺寸输入上达到。两种模式均存在超过 50 ms 的慢帧。[自动场景测速](../experiments/grade_matched_review_v1/field/latency_scene.json) · [已知单果测速](../experiments/grade_matched_review_v1/field/latency_single.json)

## 运行本轮候选

在本项目的 F 盘目录打开 PowerShell。带 `-GradeDirectory` 使用本轮冻结权重；省略该参数沿用原模型。输入图片路径替换为自己的文件。

```powershell
.\run_apple_quality.ps1 -Image 'F:\样图\苹果.jpg' -LongEdge 1280 -GradeDirectory '.\experiments\afruit_grade_matched_v1\paired'
```
