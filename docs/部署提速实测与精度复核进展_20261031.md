目前保留的精度基线仍为原 Base＋Small 四视图 **P＝94.4343%、R＝90.0261%**。本轮没有训练或换成学生模型，两份原权重严格恢复，测试前后权重和冻结源码核验一致。设备为本机 RTX 4060 Laptop GPU（8188 MiB），不是 RTX 3080 的结果。

## 1. 先确认耗时来自哪里

对固定随机清单的前 3 张图做 FP32、单图、短边 1024 的同步分段剖析，预热 2 帧。原 Base 每图产生 1000 个 RPN proposals，ROI chunk＝8，即执行 125 个掩膜计算块，最终 NMS 输入 600 个候选。

| 阶段 | 每图平均耗时 | 占模型调用约 4284.16 ms 的比例 |
|---|---:|---:|
| V/H/A 掩膜预测网络 | 2960.51 ms | 69.1% |
| 最终 exact tiled dual-mask NMS | 538.10 ms | 12.6% |
| 掩膜 ROI 特征池化 | 269.11 ms | 6.3% |
| 遮挡证据 verifier | 214.16 ms | 5.0% |
| 可见区域门控分类 | 102.07 ms | 2.4% |
| Backbone＋FPN | 149.16 ms | 3.5% |
| RPN | 18.99 ms | 0.4% |

主要瓶颈是逐候选的 ROI 掩膜网络，不是单独的骨干或 RGB 解码。同步计时会增加开销，而且部分计时为嵌套包含关系，不能把所有父阶段与子阶段相加，也不能用这份 3 图诊断直接宣称部署吞吐率。依据：[FP32 分段原始记录](F:/研究生毕业设计/模块一定位补偿以及预测/apple_detection/reports/fast_deploy_20261031/profile_fp32/profile_results.json)。

原 Base 实际启用了 `use_amodal_refinement=True`、独立 H 塔、A-base 和 verifier。完整 A 条件分支参与最终结果，不能把它当作无用计算跳过；本轮 `skip_dead_amodal=False`。

### 相同 3 张图的优化前后分段

随后用 FP16、chunk64、前 NMS 0.35 对相同 3 张图再次同步诊断，预热同为 2 次。按互不重复的主要工作分组汇总如下：

| 分组 | 实际定义 | 原 FP32＋chunk8 | 候选 FP16＋chunk64 |
|---|---|---:|---:|
| t1 | RGB 读取＋预处理 | 35.98 ms | 39.05 ms |
| t2 | Backbone/FPN＋RPN | 168.16 ms | 77.07 ms |
| t3 | ROI 掩膜预测、门控与 verifier 等完整 `roi_predictions` | 3566.75 ms | 1943.66 ms |
| t4 | 最终精确 NMS，候选路径包含最终得分过滤 | 538.10 ms | 127.24 ms |
| t5 | 输出解码＋选中 V/A 的原图尺度二值投影 | 18.06 ms | 7.35 ms |

上述分组没有包含输入传输、ROI 框分支剩余工作、最终输出筛选及其他残差，不应要求五项相加等于整个端到端耗时。该轮同样使用逐阶段同步，仅用于定位变化，不能直接当作 FPS benchmark。

其中掩膜网络从 2960.51 ms 降到 1766.78 ms，仍然是最大耗时项；ROI 块数由 125 次减少为 16 次，1000 个 proposals 没有在掩膜网络前被删除。该优化后 profile 的最终框/分数与先前同配置 FP16 benchmark 的 3 张图核验差值均为 0，说明计时包装没有改变该候选的输出；这不是它与原 FP32 逐像素相同的证明。依据：[优化后分段 JSON](F:/研究生毕业设计/模块一定位补偿以及预测/apple_detection/reports/fast_deploy_20261031/profile_fp16_v1/profile_results.json)、[模块对照原表](F:/研究生毕业设计/模块一定位补偿以及预测/apple_detection/reports/fast_deploy_20261031/profile_fp16_v1/profile_comparison.md)。

## 2. 四种运行方式的真实计时

快速路径设置为 FP16、ROI 卷积 autocast、chunk＝64，ROIAlign、解码、最终概率及 NMS 保持 FP32；NMS 仍调用原精确像素投影实现。Base 全图、Small 全图和四视图使用前 NMS 最终分数阈值 0.35、最终输出阈值 0.75；512 局部模拟使用前 NMS 和最终阈值 0.70。

| 运行方式 | 本次 n / 预热源帧 | 原 FP32 均值 / p95 | 原 FPS | 快速路径均值 / p95 | 快速路径 FPS |
|---|---:|---:|---:|---:|---:|
| Base 全图，原图单视图＋V/A 二值掩膜 | 8 / 3 | 4399.52 / 4546.75 ms | 0.2273 | 2100.47 / 2236.84 ms | 0.4761 |
| Small 全图，原图单视图＋V/A 二值掩膜 | 8 / 3 | 4569.36 / 4820.32 ms | 0.2188 | 2113.38 / 2215.93 ms | 0.4732 |
| Small 512×512 中心局部模拟＋V/A 二值掩膜 | 8 / 3 | 无对应实测 | — | 1963.40 / 1989.46 ms | 0.5093 |
| Base＋Small，原图/翻转四视图框融合 | 8 / 3 | 18857.43 / 21329.42 ms | 0.0530 | 8593.92 / 9114.86 ms | 0.1164 |

FPS 均按 **1000 / 每个源图平均延迟** 计算，四视图没有乘以 4。原 FP32 单模型为 8 张图各 2 轮、n＝16，每模型预热 10 次；原四视图 n＝8、预热 2 个源帧。快速路径每种方式 n＝8、预热 3 个源帧，另有独立的 3 图同步分段诊断，不能把诊断帧混入主计时。两份记录使用同一固定 8 图清单，但重复次数、预热和模型驻留情况有差异，不是严格的单变量统计实验。

快速路径主计时从已解码 CPU RGB 开始，包含预处理、传输、模型、解码、最终筛选和相应输出端工作；单模型计入原图尺度 V/A 二值 crop 投影，四视图仅计入框/分数融合。排除模型加载、校验、磁盘解码、绘图、相机采集和机器人通信。快速 benchmark 中 Base、Small 同时驻留 GPU，没有 CPU offload。不能把这些 FPS 直接当作相机到机械臂的全系统频率，也不能套用到逐次重新加载模型的单图 CLI。

Base、Small、四视图的原路径/快速路径平均延迟比分别约为 2.09、2.16、2.19，但绝对速度仍低于 1 个源帧/秒。**本轮尚未达到实时视觉闭环。** 没有实测 TensorRT、相机连续流或机器人控制周期。

## 3. 前 NMS 筛选与 AMP 的数值边界

“前 NMS”是指**最终 V/H/A、门控分类和 verifier 得分算完之后，进入 NMS 之前**。它不是在未校准的初始分类 logits 上先删 ROI。当前最终分类依赖掩膜，1000 个候选的 V/H/A 网络仍需计算，不能把阈值 0.35 描述成已经省掉大部分掩膜卷积。

在原 Base 的前 3 张图上，FP32、原 chunk＝8、前 NMS 阈值 0.75 与原路径最终 score≥0.75 的框、分数、V/A ROI 概率逐张量完全一致。该结论只覆盖这组设置和这 3 张图。chunk 改成 32 后，框和 V/A 在这组图上仍相同，但分数最大差为 `2.3842×10⁻⁷`，已经不是严格逐位相同。

FP16＋chunk64 的 3 图对照中，保留顺序上的最大框坐标差约 4.8878 个原图像素、分数差约 0.004222；V/A 原始 ROI 概率最大差分别约 0.8773、0.6452。它们是按保留顺序比较的原始数值差，不是 GT 掩膜 IoU、Dice 或逐图误差比例，也不能据此直接断言目标身份一致。batch2 的一张翻转图在固定 0.75 处还出现原参考 2 个、候选 3 个检测的数量变化。因此 AMP 和 batch2 不能声称保持逐像素结果或 P/R 不变。

依据：[真实原权重小样本数值检查](F:/研究生毕业设计/模块一定位补偿以及预测/apple_detection/reports/fast_deploy_20261031/probe_base_v1/probe_status.json)。另有 52 项小型 CPU 测试直接覆盖冻结 NMS 的双掩膜规则、并列分数、空掩膜、阈值边界及 top-k/cap；这些机制测试也不能代替完整 VAL。[CPU 测试记录](F:/研究生毕业设计/模块一定位补偿以及预测/apple_detection/reports/fast_original_nms_cpu_tests_20261031.xml)。

## 4. 0.35 阈值对旧 FP32 融合缓存的影响

为隔离删除低分融合成员的影响，另外对原四层 post-NMS 缓存按 `np.float32(.35)` 筛选。完整绑定为 814 图、3449 GT、13 空图；保持原框、分数、顺序及 GT，原单视图 score≥0.75 的预测身份全部保留。原未筛选融合直接读已验证缓存，没有重新融合。

| 工作点 | 原 FP32 融合 | 筛选后的旧 FP32 缓存融合 |
|---|---|---|
| 固定置信度 0.75 | P94.4343%、R90.0261%；3105/183/344 | P94.2762%、R90.2580%；3113/189/336 |
| 各自最优 P@R≥90 | P94.4343%、R90.0261%；3105/183/344 | P94.2996%、R90.1711%；3110/188/339 |
| Balanced | P92.7494%、R92.7225%；3198/250/251 | P＝R＝92.5196%；3191/258/258 |

表中数量均为 TP/FP/FN。四层候选总数从 850510 减少到 15827，融合候选从 378073 减少到 4510；固定 0.75 下有 14 张图的 TP/FP/FN 改变。低分成员会影响融合框、加权分数和架构一致性奖励，不能把 0.35 过滤称为融合零损失。快速入口因此默认 `pre-nms-threshold none`，不是默认 0.35。

**这份诊断是旧 FP32 预测缓存复算，不是重新加载权重推理，不是 FP16 精度结果，也不是速度测试。** 依据：[缓存阈值完整审计](F:/研究生毕业设计/模块一定位补偿以及预测/apple_detection/reports/fast_deploy_20261031/cached_cutoff035_audit/audit_summary.json)。
